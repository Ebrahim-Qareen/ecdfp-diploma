The incident that runs through the course

Staged on EVI-SRC01, imaged in S2, and cut deeper every session afterwards. One chain, one image, one timeline.

  1. a malicious document arrives
  2. malware executes and establishes persistence
  3. a C2 beacon opens
  4. RDP lateral movement
  5. collection and staging of the data
  6. exfiltration to a USB device

Ransomware tooling is staged on the host and never fired — the absence is part of the case, and reporting it correctly is part of the grade. The company, the users and the addresses are fictional; there is no real personal data and no live malware anywhere in the evidence.

How a session cuts the incident. S3 examines the document that started it. S4 recovers what was deleted while staging. S5 establishes which user ran what, and which device was attached. S6 puts the network evidence beside the host evidence and builds the timeline.

How the questions are written

Every case

At least one question in every case has “this artifact cannot prove that” as its correct answer. Recognising the limit of an artifact is graded exactly like finding one.

Never asked

No question has a password, hash, key or a person's personal data as its answer. You are asked which account was used, which device was attached, how many records were staged — never the value itself. Secrets enter a report by reference only: path, offset, timestamp, record count.

Answer keys are instructor-only and are not published on this site.
