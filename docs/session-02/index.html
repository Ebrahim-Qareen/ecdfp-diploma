Session 02

Acquisition — Disk, Memory & Live Response

By the end of today you can collect what is decaying, image what is not, and state precisely what your image does and does not cover.

EVS-02 EVS-03 EVS-04 Case 02 FIN-WKS-07
Where this sits

Second of six. Session 1's evidence arrived cold and sealed. Today it arrives powered on, with a user still logged in, and every second costs you something.

How this session works

Four hours, and the clock is already running

One word taught twice, on purpose

Session 1 read verified in a log it was handed. Today you produce that log yourself and read it again. Different lesson, same word — page 14.

Objectives

By the end of this session you can

  1. Order a collection by what decays fastest, and justify the order out loud.
  2. Capture memory with a named tool and confirm the capture completed.
  3. Choose between E01, raw and AD1 for a stated purpose.
  4. Detect storage the drive is not reporting, before you image it.
  5. Say exactly which link in the acquisition chain the word verified covers.
The claim

“Pull the plug, then image it properly.”

FIN-WKS-07 — as first responders found it
power : ON
logged in : l.bennett, session active 4 d 6 h
established : 1 outbound connection, port 443
RAM : 16 GiB — not captured
disk : mounted, read-write
Everything on the red line stops existing the moment the plug comes out.

The instinct is clean, defensible and comes from Session 1: never work on a live original. It is also the single most expensive mistake in this room, and today is about why.

The claim on trial today

Powering down first is the safe choice because a cold disk is what you can image properly.

S2-01 · 15 min

What is disappearing while you decide

Do it now

You have sixty seconds and one operator. Put these six in collection order and write the order down: browser history · open sockets · running processes · the disk · ARP cache · last night's backup.

What the order cannot do

Nothing here recovers what has already gone. The order buys you what is left, and the rest is a limitation you write down.

S2-02 · 20 min

Memory, and what only lives there

Only in RAMAlso on disk, later
Running processes and their memorythe executable file itself
Established network connectionsfirewall and proxy logs
Injected and fileless code— nothing, if it never touched disk
Decrypted keys, clipboard, typed text— nothing
Unsaved documents— nothing
winpmem_mini_x64_rc2.exe — capture
> winpmem_mini_x64_rc2.exe FIN-WKS-07.raw
Driver loaded.
Padding 0x0 - 0x1000
Wrote 17 179 869 184 bytes
Done.
Write the capture to external media, never to the machine you are capturing.
Three ways this goes wrong

Capturing to the local disk overwrites the unallocated space you may need · a capture smaller than installed RAM is truncated, not compressed · the acquisition tool itself occupies memory, and you record that it did.

S2-03 · 25 min

Scope, and the container you put it in

Pick the container for each

1 · the case may go to court and the drive is 2 TB of mostly empty space. 2 · you need one folder from a running file server tonight. 3 · the tool on the other side reads nothing but sectors.

What a logical container gives up

Deleted files, slack, unallocated space and anything outside the selection are not in an AD1. It is the right answer sometimes, and never by accident.

S2-07 · 8 min

Storage the drive does not admit to

hdparm -N /dev/sdb — before imaging
$ sudo hdparm -N /dev/sdb
/dev/sdb:
max sectors = 800000000/976773168, HPA is enabled
# the second number is the truth
Two numbers. When they differ, your image is short before you start.
Run this before the imager

A host-protected area is set by the host; a device configuration overlay is set in the drive's own firmware and survives a wipe. Record both sector counts — section 6, Findings — whether they differ or not.

S2-04 · 20 min

FTK Imager, end to end

  1. Attach the source through the write blocker. Record its model, serial and mode.
  2. Create Disk Image → Physical Drive → select the source.
  3. Choose E01. Fill case number, examiner and description — they are written inside the container, not beside it.
  4. Set fragment size and compression. Tick Verify images after they are created.
  5. Read the resulting .txt log and copy its digests into your report.

S2-05 · 12 min

A second tool, and why you run one

dc3dd — imaging with a digest in one pass
$ dc3dd if=/dev/sdb of=usb.img hash=sha256 log=usb.log
9767728+0 sectors in
9767728+0 sectors out
sha256 total: 4c1e… (see usb.log)
# the log is the artifact, not the terminal
One pass writes the image and its digest together.
Why a second tool at all

Two independent implementations agreeing is evidence. One tool agreeing with itself is not. When they disagree, the structure you learned to read by hand is what settles it.

Targeted triage is a subset, not a smaller image

A triage collection takes named artefacts — registry hives, event logs, prefetch, $MFT. It is not an image at lower resolution, and it cannot be treated as one.

Independent practice

On your own image

  1. Mount your E01 read-only. Record the tool, its version and the mount options.
  2. Export three files of different types out to your working folder.
  3. Read the first four bytes of each and tabulate claimed type against actual.
  4. Write one finding about the file that disagrees, naming its exact path.
  5. Unmount, then re-verify the image against the digest from your acquisition log.
⛔ Provisional — pending EVS-02

The steps, the order and the verification line are final. There is no image to mount until the disk acquisition is done, so no path, size or digest on this page is real yet.

Takeaways

Five things to leave with

1

Collection order is forced by decay rates, not by preference.

2

A memory capture smaller than installed RAM is truncated. Size is the check.

3

Ask the drive for its true sector count before you image, never after.

4

verified covers the tool's own write and read-back. The source is read once.

5

Name every tool and its version. “A collector was run” is not a method.

And the one carried from Session 1

“Cannot be determined” is a professional answer. Today it is the correct answer to at least one thing you were asked.

Why section 9 is the long one today

Acquisition is the one stage whose honest output is mostly about what you cannot claim. An image that is complete and an image that is verified are different sentences, and the report has to say which one you have.
