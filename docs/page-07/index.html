T11 · Bridge

Where we are أين نحن الآن

A document and an executable are both containers with a declared structure. That structure can be read field by field, cheaply, offline, and with the file never handed to the thing that would run it. المستند و الملف التنفيذي كلاهما container ذات بنية مُعلَنة. و يمكن قراءة تلك البنية حقلاً حقلاً، بتكلفة قليلة، دون اتصال، و دون أن يُسلَّم الملف أبدًا إلى ما قد يشغّله.

The rule that governs this whole page
  • Static analysis reads. It never runs. A file that is opened is a file that has already acted. التحليل الساكن يقرأ و لا يشغّل أبدًا. فالملف الذي يُفتح ملفٌّ قد فعل فعله بالفعل.
  • Everything you can state from this page comes from bytes and offsets, which another examiner can reproduce. كل ما تستطيع تقريره من هذه الصفحة مصدره bytes و إزاحات، يستطيع فاحص آخر إعادة إنتاجها.

T11 · Theory

Two document families عائلتا المستندات

Microsoft Office has written documents in two fundamentally different containers, and both are still in evidence today because Word opens both. كتب Microsoft Office المستندات في حاويتين مختلفتين اختلافًا جذريًّا، و كلتاهما ما زالت تظهر في الأدلة اليوم، لأن Word يفتحهما معًا.

Why the signature check is not enough here

Every OOXML document, every JAR, every APK and every ODF file begins 50 4B 03 04. So a signature match tells you “some ZIP” and nothing more — you have to open the container and read the parts to know what kind of document you are holding. كل مستند OOXML، و كل ملف JAR، و كل APK، و كل ODF يبدأ بـ50 4B 03 04. فتطابق الـ signature يقول لك «أرشيف ZIP ما» و لا شيء أكثر — و عليك فتح الـ container و قراءة الأجزاء لتعرف أي نوع من المستندات بين يديك.

T11 · Theory · measured

A .docx is a ZIP ملف الـ .docx أرشيف ZIP

Take an ordinary Word document and unzip it. This is handover_notes.docx, authored for this page: 3,111 bytes, five parts, and the text you can see is the smallest of them. خذ مستند Word عاديًّا و فُكّ ضغطه. هذا هو handover_notes.docx، المؤلَّف من أجل هذه الصفحة: ٣٬١١١ byte، و خمسة أجزاء، و النص الذي تراه هو أصغرها.

What listing the parts answers, for free

Whether the document contains code. A macro lives in word/vbaProject.bin. If that part is not in the listing, there is no VBA project in the file — and you established that without opening Word and without executing anything. هل يحتوي المستند على كود. فالـ macro يعيش في word/vbaProject.bin. و إن لم يكن هذا الجزء في القائمة فلا مشروع VBA في الملف — و قد أثبتّ ذلك دون فتح Word و دون تنفيذ أي شيء.

T11 · Theory · the sentence this half turns on

What a macro proves ما الذي يُثبته وجود الـ macro

Finding word/vbaProject.bin in a document is a real finding. It is also a much narrower finding than almost everyone writes. العثور على word/vbaProject.bin داخل مستند finding حقيقي. و هو أيضًا finding أضيق بكثير مما يكتبه الجميع تقريبًا.

What it proves

Code is present in the file. That is the whole of it, and it is worth stating precisely because it is reproducible: the part is either in the container or it is not. أن كودًا موجود في الملف. هذا كل ما فيه، و يستحق الصياغة الدقيقة لأنه قابل لإعادة الإنتاج: فالجزء إمّا في الـ container و إمّا ليس فيها.

The four things it does not prove

#1 That the macro ran. #2 That macros were enabled on the host. #3 That the user clicked Enable Content. #4 That the code is hostile — legitimate business documents carry macros every day. ١ أن الـ macro عمل. ٢ أن الـ macros كانت مفعَّلة على الجهاز. ٣ أن المستخدم ضغط Enable Content. ٤ أن الكود خبيث — فالمستندات المهنية المشروعة تحمل macros كل يوم.

And the reverse fails too

The absence of a macro does not make a document harmless. The second delivery path needs no macro at all: a crafted file that exploits a vulnerability in the application that opens it. “No macro found” is not “not malicious”. و غياب الـ macro لا يجعل المستند سليمًا. فمسار التسليم الثاني لا يحتاج macro إطلاقًا: ملف مُعَدّ يستغل ثغرة في التطبيق الذي يفتحه. فـ«لم يُعثر على macro» ليست «غير خبيث».

The report sentence

“The document contains a VBA project at word/vbaProject.bin. No evidence in this file establishes whether it was executed.” Two sentences, both reproducible, and the second one is the reason the first will survive. «يحتوي المستند على مشروع VBA في word/vbaProject.bin. و لا يوجد في هذا الملف ما يُثبت ما إذا كان قد نُفِّذ.» جملتان، كلتاهما قابلة لإعادة الإنتاج، و الثانية هي سبب صمود الأولى.

T11 · Theory · measured

From MZ to the real header من MZ إلى الـ header الحقيقي

Every Windows executable begins 4D 5A. Those two bytes are a 1980s DOS header that no modern system uses — the real header is somewhere else, and the file tells you where. يبدأ كل ملف تنفيذي في Windows بـ4D 5A. و هذان الـ byte header بصيغة DOS من الثمانينيات لا يستخدمها أي نظام حديث — فالـ header الحقيقي في مكان آخر، و الملف نفسه يدلّك عليه.

Measured from a published, benign binary

The file used throughout this page is _imagingmorph.cp312-win_amd64.pyd from Pillow 12.3.0, 12,288 bytes. Its e_lfanew is 0x110, and 50 45 00 00 sits at exactly that offset. الملف المستخدم في هذه الصفحة كلها هو _imagingmorph.cp312-win_amd64.pyd من Pillow 12.3.0، و حجمه ١٢٬٢٨٨ byte. و قيمة e_lfanew فيه 0x110، و 50 45 00 00 يقع عند تلك الإزاحة بالضبط.

T11 · Theory · measured

Sections, and what entropy is for الأقسام، و ما فائدة الـ entropy

A PE is divided into named sections, each with a size and a set of permissions. Entropy measures how unpredictable a section’s bytes are — and its value is only useful if you know what normal reads. ينقسم ملف الـ PE إلى أقسام مسمّاة، لكلٍّ منها حجم و مجموعة صلاحيات. و يقيس الـ entropy مدى صعوبة توقُّع bytes القسم — و قيمته لا تفيد إلا إذا كنت تعرف قراءة الطبيعي.

What a high entropy value establishes

That the region is compressed, encrypted, or random. Measured here: compressed reads 7.96 and random reads 7.95 — entropy cannot distinguish them, and it certainly cannot distinguish either from malice. Installers, media and legitimate protected software all read high. أن المنطقة مضغوطة أو مشفَّرة أو عشوائية. و القياس هنا: المضغوط ٧٫٩٦ و العشوائي ٧٫٩٥ — فالـ entropy لا يفرّق بينهما، و لا يفرّق بالتأكيد بين أيٍّ منهما و بين سوء النية. فالمثبِّتات و ملفات الوسائط و البرامج المحمية المشروعة كلها تقرأ عاليًا.

So what it is actually for

Triage. It is a cheap way to sort a thousand files into ordinary and look at this one. That is a real and useful job. It is a reason to look, never a finding you write down. الفرز. فهو طريقة رخيصة لتقسيم ألف ملف إلى عادي و انظر إلى هذا. و هذه وظيفة حقيقية و مفيدة. لكنه سبب للنظر، لا finding تكتبه.

T11 · Theory · measured

Imports are a capability list جدول الـ imports قائمة قدرات

A PE declares, in the file, every operating-system function it intends to call. Reading that list tells you what the file is able to do — before it does anything. يُعلن ملف الـ PE، داخل الملف نفسه، كل دالة في نظام التشغيل ينوي استدعاءها. و قراءة تلك القائمة تخبرك بما يستطيع الملف فعله — قبل أن يفعل أي شيء.

What the absence says

This binary imports 30 functions across four libraries, and none of them opens a socket, writes to the registry, creates a process or enumerates a directory. That is a statement about capability, and it is reproducible from the file. يستورد هذا الملف ٣٠ دالة من أربع مكتبات، و لا واحدة منها تفتح socket أو تكتب في الـ registry أو تُنشئ عملية أو تُعدّد مجلدًا. و هذه عبارة عن القدرة، و هي قابلة لإعادة الإنتاج من الملف.

And the trap on the other side

A binary that imports only two or three functions is not simple — it is usually packed, and it will resolve everything else at run time where a static reader cannot see it. A short import table is a louder signal than a long one. أما الملف الذي يستورد دالتين أو ثلاثًا فقط فليس بسيطًا — بل غالبًا محزوم، و سيستدعي كل ما عداها وقت التشغيل حيث لا يراها القارئ الساكن. فجدول الـ imports القصير إشارة أقوى من الطويل.

T11 · Theory

What strings prove ما تُثبته الـ strings

Running strings over a binary is the cheapest check there is, and the most over-read. It returns every printable run of bytes — which is not the same as every message the program has. تشغيل strings على ملف ثنائي أرخص فحص موجود، و أكثرها تحميلاً فوق طاقته. فهو يُعيد كل تتابع bytes قابل للطباعة — و هذا ليس كل رسالة في البرنامج.

How a strings result is written honestly

“The file contains the printable sequence http://<host>/update at offset 0x2A40.” That is a finding. “The malware contacts <host>” is an interpretation that this file cannot support — contact is proved by network or host evidence, not by a byte sequence. «يحتوي الملف على التتابع القابل للطباعة http://<host>/update عند الإزاحة 0x2A40.» هذه finding. أما «البرمجية الخبيثة تتصل بـ<host>» فتفسير لا يحتمله هذا الملف — إذ يُثبَت الاتصال بدليل شبكي أو دليل من الجهاز، لا بتتابع bytes.

BinaryIts import table
Aالملف أKERNEL32 41 · USER32 18 · GDI32 22 · COMCTL32 9أربع مكتبات بأعداد كبيرة من الدوال

The three answers

A is a GUI application — windows, drawing, common controls. Ordinary. B imports the two functions used to resolve everything else at run time: this is the shape of a packed binary, and the static import table is deliberately empty. C declares network (WS2_32, WININET) and registry or service capability (ADVAPI32) — which is a capability finding, and still not a verdict. أ تطبيق بواجهة رسومية — نوافذ و رسم و عناصر تحكم. عادي. ب يستورد الدالتين المستخدمتين لاستدعاء كل شيء آخر وقت التشغيل: و هذا شكل ملف محزوم، و جدول الـ imports الساكن فارغ عمدًا. ج يُعلن قدرة شبكية (WS2_32 و WININET) و قدرة على الـ registry أو الخدمات (ADVAPI32) — و هذه finding عن القدرة، و ليست حكمًا بعد.

Notice that B is the one that says the most while importing the least. An empty import table is not an absence of capability; it is a statement about when the capability gets resolved. لاحظ أن ب هو الذي يقول أكثر شيء بأقل استيراد. فجدول الـ imports الفارغ ليس غيابًا للقدرة، بل عبارة عن توقيت استدعاء تلك القدرة.

Cheat sheet — documents, PEs, and the one rule ورقة المراجعة — المستندات و الـ PE و القاعدة الواحدة

The page condensed to what you read off a file without running it. الصفحة مختصرة فيما تقرؤه من ملف دون تشغيله.

  • Two document families — legacy OLE (.doc/.xls) · OOXML (.docx/.xlsx), which is a ZIP of XML parts.عائلتان: OLE القديمة و OOXML الحديثة، و الثانية ZIP من أجزاء XML.
  • A .docx is a ZIP. unzip -l lists its parts; word/vbaProject.bin means a macro is present. Present is a finding; malicious is not.الـ .docx عبارة عن ZIP. unzip -l يسرد أجزاءه، و vbaProject.bin يعني وجود macro. الوجود finding؛ أما “خبيث” فلا.
  • PE layout — MZ header → e_lfanew → PE signature → optional header → section table.بنية الـ PE: MZ header ← e_lfanew ← PE signature ← optional header ← جدول الـ sections.
  • Entropy is a reason to look, never a finding. .text ~5–6 · packed or encrypted ~8 — but compressed and random both read ~8.الـ entropy سبب للنظر لا finding: .text ~5–6، و المضغوط أو المشفّر ~8 — و المضغوط و العشوائي يقرآن ~8 معًا.
  • Imports are a capability list — what the binary CAN call, not what it did. Socket, registry and process APIs are candidates, not acts.الـ imports قائمة قدرات — ما يستطيع الملف استدعاءه، لا ما فعله. دوال الشبكة و الـ registry و العمليات مرشّحات لا أفعال.
  • Strings are candidates, not proof. A URL in a binary is a string; that it was contacted needs other evidence.الـ strings مرشّحات لا إثبات. الـ URL داخل ملف مجرد نص؛ و أن يكون اتُّصل به يحتاج دليلاً آخر.
  • Every over-claim is one adjective past the evidence. “vbaProject.bin present” is reproducible; “contains a malicious macro” is not.كل ادّعاء زائد صفة واحدة بعد الدليل. “vbaProject.bin موجود” قابل للتكرار؛ “يحوي macro خبيثًا” لا.
