Three machines · one host · no network

The lab

VMware Workstation only. No cloud, no SIEM, no internet. Evidence is handled on machines that cannot reach anything, which is what makes the handling defensible. Everything about the lab is on this one page: the topology, the machines, what to have ready, the workstation build, and the snapshots.

Topology

One host-only network inside one VMware host. EVI-SRC01 is compromised and then imaged; Kali takes and hashes the image; the verified image is examined on FOR-WS01. Evidence flows one way, and nothing on this network can reach the internet.

Before your first session

Have these ready
  • 250 GB free on the host, and VMware Workstation installed.
  • FOR-WS01 built and snapshotted — the build below takes about 90 minutes and is done before class, not during it. Building the workstation is not a use of class time; using it is.
  • The session's evidence downloaded and hash-verified before class — the page for each topic tells you which set and gives you the hash.

Build FOR-WS01 — the analyst workstation

Three parts, in order. Build the Windows VM, install the tool set by script, verify and snapshot. The victim EVI-SRC01 and Kali are not yours to build.

Part A · ~40 minThe Windows 11 VM — install, update, harden, first snapshot.
Part B · ~40 minThe 25 tools, installed by one script (or session by session).
Part C · ~10 minVerify, shortcuts, isolate the network, the CLEAN-TOOLS snapshot.

About the network setting. The build needs internet (Windows Update and the tool downloads), so Part A sets the adapter to NAT. Evidence handling must not have internet, so Part C switches it to Host-only before the final snapshot. From that point on the topology above is true: nothing leaves the host.

Part A · the Windows 11 VM

  1. Get the ISO — Windows 11 Enterprise Evaluation (free, 90-day, ~6 GB).
  2. New VM in VMware — point to the ISO, guest Windows 11 x64, name FOR-WS01. Encrypt “only the files needed for a TPM”.
  3. Hardware — 8 GB RAM, 4 CPU, disk 120 GB, network NAT (for the build only — switched to Host-only in Part C).
  4. Install Windows — boot the ISO, Custom, pick the 120 GB disk. No product key needed.
  5. VMware Tools — VM → Install VMware Tools, run setup64.exe, reboot.
  6. Update & harden — Windows Update until clean; then Device encryption OFF, OneDrive sync off, sleep Never.
  7. Snapshot CLEAN-BASE — shut down, take a snapshot before any tools. Cheap insurance.

Part B · install the tools

⇩ Download all (.zip) — or grab a single session below. Click any box to download that script. Run in an elevated PowerShell; if Windows blocks them: Get-ChildItem .\*.ps1 | Unblock-File.

Part C · finish

  1. Verify — run verify_tools.ps1. Every row should read PASS (0 missing).
  2. Shortcuts — run create_shortcuts.ps1 to put the GUI tools on the desktop.
  3. Isolate the network — shut down; VM → Settings → Network Adapter → Host-only. The build needed internet; evidence handling must not. This is what makes the topology above true.
  4. Snapshot CLEAN-TOOLS — take the snapshot now, on the isolated machine. Never delete it — every session rolls back here.

Snapshot policy

One snapshot per session on FOR-WS01, taken before you touch evidence.

  • CLEAN-TOOLS — taken once the tool set is installed, verified, and the network is host-only. Never delete this one. Every later session is recoverable from it.
  • S0N-START — taken at the start of each session, before any evidence is mounted.
  • EVI-SRC01 is snapshotted by the instructor before staging, so the compromise can be re-run.
Caveat

A snapshot is not a forensic copy and never appears in a chain-of-custody form. It protects your workstation, not the evidence — the evidence is protected by hashes and by working only on a copy.
